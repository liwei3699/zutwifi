# ZutWifi · 校园网自动登录

连上学校 WiFi 之后，在后台把校园网认证做完，不打开浏览器。Windows 10/11，单个 exe。

> 学生自制工具，与学校、网络中心无关。校园网账号密码只留在你自己机器上（见下面「隐私」一节）。

## 它做什么

- **自动登录**：检测到连上 `zut-stu`（SSID 白名单可在设置里改）就在后台提交认证，1.5 秒去抖，不需要点任何东西。
- **不碰浏览器**：直接按门户的 HTTP 契约走，全程不弹任何网页。
- **认证之后再看外网**：门户说"认证成功"和外网真的通是两件事，所以判定之后还要过一次连通性检查；只认证通过、外网不通时会明确告诉你"已认证，但暂时上不了网"，而不是假装成功。
- **系统通知**：登录成功 / 失败 / 认证失效 / 注销，走 Windows 通知中心；通知中心不可用时自动退化成托盘气泡，不会一声不吭。
- **在线时长**：登录后那个数字像秒表一样一秒一秒往前走（不是等刷新才跳一下）。
- **手动注销、一键注销并重登**：程序自己从不发注销包；账号被别处的旧会话挡住时，界面上会出现「注销并重登」。
- **别的 WiFi 上完全不工作**：连手机热点、图书馆 WiFi（不在白名单里）时它不探测、不登录、不注销。
- **出问题能自救**：命令行自检通道 + 一键导出诊断包，日志里对门户的每一次调用都留一行原始判定。

## 快速开始

1. 下载 release 里的 `ZutWifi.zip`，把三个文件解压到一个**不会随便删的固定目录**（例如 `D:\Tools\ZutWifi\`）。开机自启记的就是这个路径，移动过 exe 要重新勾一次。
2. 双击 `ZutWifi.exe`。第一次会弹配置窗口：学号、校园网密码、运营商后缀（移动 `@cmcc` / 电信 `@telecom` / 联通 `@unicom`）。
   密码就按你平时在网页上输的那样填，**不要多带逗号或空格**。
3. 点「测试配置」，看到"成功"再点「完成」。
4. SmartScreen 报"Windows 已保护你的电脑"：点「更多信息」→「仍要运行」。所有未签名软件都有这一步。

托盘图标颜色：绿=已认证、黄=正在做事、灰=没连校园网、红=失败、橙=已认证但上不了网。
点窗口右上角的 X 只是收进托盘，要退出请右键托盘图标 → 退出。

## 它是怎么判断成功还是失败的

门户是 Dr.COM eportal。这套判据是从真机抓包里一条一条对出来的，也是这个项目里最值得记的部分：

| 要判的事 | 做法 |
|---|---|
| 认证成功没有 | **只看 302 的 `Location` 头**：跳 `/3.htm` = 成功，跳 `/2.htm` = 失败。响应体里的"成功"字样不算数。 |
| 为什么失败 | `Location` 上的 `ErrorMsg` → URL 解码 → Base64 → **GBK**（代码页 936）。这个门户的页面不是 UTF-8。 |
| 现在到底认没认证 | `GET http://1.1.1.1:9002/0`（禁用自动跳转）：`302` 回门户 = 没认证；`200` 且页面里有 `<title>Logout</title>` = 已认证。极性与直觉相反。 |
| 本机现在几个 IP | 校园网是 DHCP，换网络就换地址，拿旧 IP 提交必被拒。`GET http://1.1.1.1/a70.htm` 在两种状态下都可达，页面里服务端注入的 `ss5="x.x.x.x"` 就是门户眼里的那个 IP。 |
| 登录要不要 Cookie | 不要。零 Cookie 也能完成整轮认证。 |
| 要不要保活 | 不要。门户页面里那个 5 秒轮询是登录页在等扫码，不是会话心跳；登录后不需要持续发包。 |

## 隐私与安全

- 密码用 Windows DPAPI 加密，只对**这台机器 + 这个 Windows 用户**可解，存在 `%APPDATA%\ZutWifi\secret.bin`。换电脑、重装系统、换登录账户都要重填一次——这是设计，不是 bug。
- 密码不进 `settings.json`、不进日志、不进通知、不进诊断包。日志里只留 `upass=***(len=10)` 这种脱敏摘要（连长度都是编码后的长度，与原口令不必相同）。
- 出网的地址只有：学校门户 `1.1.1.1`（认证、探测、取 IP）与两个连通性探针目标（`msftconnecttest` / `bing`，只读）。没有遥测、没有检查更新、不上传任何文件。
- 诊断包里**含**本机 MAC、计算机名、Windows 用户名与 IP——排障要靠它们核对是哪一次会话。所以它只该发给帮你看问题的人，不要贴进群组或公开场合。

## 失败时候的规矩（保守档位）

一次连接里只登一次：失败就按 2s / 5s / 15s 退避，一共四次提交，然后停手并告诉你原因，之后**不会**再自动重试。要恢复得你点一下「登录」。
这么设计是因为反复重试会把账号刷进门户的锁定策略里——那是比"这一次没登上"严重得多的后果。

同理：中途换了网络，这一轮会被判过期并中止，不会拿着旧接入点的身份继续提交。

## 从源码构建

需要 .NET 10 SDK（目标框架 `net10.0-windows10.0.19041.0`）与 Git Bash / PowerShell。

```bash
dotnet test ZutWifi.sln          # 全量用例（546 条，其中 1 条需要真机的属性系统，故意跳过）
powershell -ExecutionPolicy Bypass -File ./build.ps1
python tools/make-icons.py       # 只有改了 assets/ 里那张校徽时才需要
```

`build.ps1` 做四件事，顺序是有讲究的：先删掉上一轮的交付产物 → 全量测试当闸门 → 单文件自包含发布并打包 → 拿真产物再核对一遍（zip 里恰好三个条目、包里的说明文字与磁盘上那份逐字相同）。
它**不跑** `--selftest`：那一步会真向门户提交一次登录，不属于打包。

产物：`dist/ZutWifi.zip` = `ZutWifi.exe` + `使用说明.txt` + `自检.bat`。

## 自检与诊断

```
ZutWifi.exe --selftest                  # 十步：设置 → DPAPI → 无线 → 探测 → 取 IP → 登录 → 复检 → 外网 → 日志落盘
ZutWifi.exe --selftest --with-logout    # 额外真发一次注销（会把你当前会话踢下线）
```

退出码只有三个：`0` 整轮跑完且没问题、`1` 跑完了但发现问题、`78` 这一轮没跑成（结论不可信）。
在一台没配过账号的机器上跑出自检退出码 `1` 是**正常**的——那说的是"有几步没测到"，不是"程序坏了"。
日志在 `%APPDATA%\ZutWifi\logs\`，主窗口右下角也能直接导出诊断包。

## 目录结构

```
src/ZutWifi/
  Portal/       门户契约：URL 与表单体、错误码表、判据（唯一出网的出口）
  Core/         状态机、重试与退避、连通性探测、时钟
  Wifi/         wlanapi P/Invoke、SSID 解码与白名单匹配、看门狗
  Notify/       通知中心 Toast + AUMID 注册 + 托盘气泡回退
  Shell/        主窗口、托盘、设置页、首次向导、状态呈现、图标
  Config/       设置存储、DPAPI 密码、开机自启
  Diagnostics/  事务日志与脱敏、自检通道、诊断包
tests/ZutWifi.Tests/   xUnit 用例（含对着真产物核对说明与交付物的一组）
docs/superpowers/      设计说明与逐任务实现计划
assets/ + tools/       校徽原图、生成的 ico/png 与生成脚本
```

## 已知限制

- **未签名**：第一次运行一定有 SmartScreen 提示；部分杀软会对"未签名 + 自包含单文件"报可疑，需要手动信任。
- **通知中心需要一个开始菜单快捷方式**（AUMID）。个别机器上那一步会失败，此时通知退化为托盘气泡，认证功能不受影响。
- **在线时长以门户给的秒数打底**，两次刷新之间本地插值。别人在自助页面把你注销掉时，它最多还会多空走约一分钟。
- **不做**：流量/用量查询、多账号切换、定时任务、代理设置、修改系统 DNS 或 IP。这些都不在范围内。
- 只支持 `zut-stu`（可改白名单）这一类 Dr.COM eportal 门户；换学校或门户改版，需要先重跑一次抓包核对契约。

## 想换成自己的图标

仓库里那份是内置的中性标记（品牌绿圆角方块 + 白 Z），由 `tools/make-icons.py` 画出来。
想用自己的徽标：把你那张图存成 `assets/logo.png`（这个路径在 `.gitignore` 里，不会被提交），
再跑一次 `python tools/make-icons.py`，重新 `build.ps1` 即可。脚本会自动把与外边连通的白底抠成透明。
